# Slim base notes

This is the reduced car setup. It keeps:

- `drive`: the `kw_f110_drive` workspace, default command `teleop`
- `system`: VESC + sensor + joystick bringup (`f1tenth_stack`), plus the
  fusion / mapping / navigation launch files that ship with the system stack

It does **not** include the GPU/RL container, `rtis_f110_rl`, `rtis_cuda`,
`rtis_safety`, `rtis_lidar_odom`, `ros_preempt`, or the cpuset experiment
scripts. Those live in the full `f1tenth_car_docker` setup.

## Start

```sh
docker compose --profile setup build base
docker compose build drive system
docker compose up discovery system drive
```

Images are tagged `:slim` (`f1tenth-base:slim`, `f1tenth-drive:slim`,
`f1tenth-system:slim`) so they do not collide with the full setup's `:latest`
images. Set `BASE_IMAGE_TAG` to use a different tag.

## Teleop

The system container starts `joy_node` and remaps the VESC's `ackermann_cmd`
input to `/teleop/drive`. The drive container runs
`ros2 run kw_f110_drive teleop`, which subscribes to `/joy` and publishes
`AckermannDriveStamped` on `/teleop/drive`.

Buttons/axes (from `teleop.cpp`): steering axis 0, throttle axis 5, reverse
axis 4, speed up button 10, speed down button 9, autonomy toggle button 0.
While autonomy is enabled, `cmd_vel` (`geometry_msgs/Twist`) is converted to
Ackermann commands, with a 0.5 s watchdog that stops the car if commands go
stale.

## System launches still available

```sh
# Normal hardware bringup (default system command)
ros2 launch f1tenth_stack bringup_launch.py

# Odometry EKF + localization (see fusion.launch.py for modes)
ros2 launch f1tenth_stack fusion.launch.py
ros2 launch f1tenth_stack fusion.launch.py localization_mode:=amcl map:=/abs/path/to/map.yaml
ros2 launch f1tenth_stack fusion.launch.py localization_mode:=slam_toolbox posegraph:=/abs/path/to/map

# SLAM / map building
ros2 launch f1tenth_stack mapping.launch.py

# Save the map built by slam_toolbox
ros2 service call /slam_toolbox/save_map slam_toolbox/srv/SaveMap "{name: {data: my_track}}"
ros2 service call /slam_toolbox/serialize_map slam_toolbox/srv/SerializePoseGraph "{filename: /abs/path/to/my_track}"
```

Note: the `lidar_odom` localization mode in `fusion.launch.py` expects
`rtis_lidar_odom`, which is not part of this slim setup. Use `amcl` or
`slam_toolbox`, or add the package back if needed.
